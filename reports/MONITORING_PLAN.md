# 每 3 天推送一次状态消息：方案计划（2026-10-25）

> **已实施 B 方案**（服务器脚本 + Telegram），见 `reports/DEPLOY_LOG.md`「监控」一节。下面是当时的方案讨论。

## 目标

每 3 天收到一条手机消息，告诉你两个模拟盘机器人是否健康、这几天赚了还是亏了、N25 新规则表现如何。
出现异常时消息里会标出来，并给出建议。**全程只读，不改服务器上的任何东西。**

## 三种做法

| | A. Claude 定时任务（推荐先用） | B. 服务器定时脚本 + Telegram | C. A + B 一起用 |
|---|---|---|---|
| 怎么工作 | Claude 桌面版每 3 天定时启动一次，SSH 上服务器只读检查，写一段中文小结，推送到你手机 | 服务器上放一个检查脚本，每 3 天由系统定时运行，通过 Telegram 机器人发消息 | B 负责实时告警，A 负责每 3 天的分析小结 |
| 你的电脑要开着吗 | **要**（Claude 桌面版要在运行） | 不用 | B 部分不用 |
| 要不要改服务器 | 不用 | 要（加一个脚本和一个定时任务） | 要 |
| 需要你准备 | 无 | 用 Telegram 的 BotFather 建一个机器人，把 token 交给服务器配置（你之前说暂缓 Telegram） | 同 B |
| 消息质量 | 能分析、能对比回测、会用人话解释 | 固定格式的数字，不会分析 | 两者兼有 |
| 成本 | 每次消耗一点 Claude 用量 | 免费 | — |
| 实时性 | 只在每 3 天那一刻 | 可以顺便做到开平仓、报错立即推送 | 最好 |

**建议：** 先上 **A**，不需要你做任何准备，也不碰服务器。以后想要「出事立刻知道」，再加 B。

## 消息内容（A 方案）

```
【交易机器人 3 日报】2026-10-28 09:00
✅ 健康：X7Safe 正常（PID 不变 / 无崩溃），Combined_V3 正常，内存剩 ~700 MB
📈 X7Safe 近 3 天：4 笔，+12.3 USDT（3 胜 1 负），最大单笔亏损 −8.1
📊 N25 新规则累计（10-25 起）：9 笔，+25.6 USDT，盈亏比 1.8
🔍 N25 交易所止损检查：已确认 3 笔普通交易止损挂在首仓价 ×0.75 ✅
🧪 回测对账（每周一次）：本周实际 vs 回测重放，复现 8/9 笔
⚠️ 异常：无
👉 建议：无需操作
```

## 每次检查的项目

| 类别 | 检查内容 | 什么情况标为异常 ⚠️ |
|---|---|---|
| 健康 | 两个机器人是否在运行、最近心跳、有没有自动重启、报错数（排除每天 00:04 的已知噪音）、服务器内存和磁盘 | 停止运行；心跳超过 10 分钟没更新；出现新的报错类型；可用内存 < 200 MB；磁盘 > 85% |
| 交易 | 上次报告之后的新交易：笔数、盈亏、最大单笔亏损、当前持仓 | 单笔亏损 > 100 USDT；3 天合计亏损 > 2%（200 USDT） |
| N25 | 新规则下（10-25 07:15 起）的累计成绩；普通交易的止损是否挂在首仓价 ×0.75 | 有普通交易的交易所止损停在 ×0.85（说明 N25 没生效） |
| 对账 | 每两次报告（约每周）跑一次回测重放，对比实际交易 | 复现率 < 80% |
| Combined_V3 | 新交易和累计盈亏 | 同「交易」 |

## 时间安排

- 每 3 天北京时间 **09:00** 一次（不在每周日 11:17 重启时段附近）。
- 第一次：设置完成后的下一个 09:00。
- 4~8 周后正式评估 N25 时，顺便评估这个推送是否需要调整频率或内容。
